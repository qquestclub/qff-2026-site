# evals.md — Evaluation

## 1. How to run

```
npm run lint          # includes the banned-adjective content lint
npm run test          # vitest — normalisation, validation, invariant tests
npm run build         # must be clean: zero errors, zero new warnings
npm run test:worker   # wrangler dev --local + integration tests against local D1
```

All four must pass before any deploy. Non-zero exit on failure.

Worker integration tests run against `wrangler dev --local` with a local D1 instance. **Do not run the test suite against the live Sheet** — it is the surface your organisers are reading.

## 3. Invariant tests

One per invariant in `CONTRACT.md`.

| ID | Invariant | Assertion |
|---|---|---|
| INV-1-T | No registration silently lost | Stub the Worker to return HTTP 500. Assert the UI renders the error state containing the fallback email, and that the success state is never mounted. Repeat for a network timeout and for an aborted request. |
| INV-2-T | One human, one row | Fire two concurrent POSTs with the same normalised email. Assert `SELECT COUNT(*) = 1`, both responses are HTTP 200, and both `registrationId` values are identical. |
| INV-3-T | PII never leaves the trusted path | Grep `out/`, `worker/src/`, and captured Worker logs for `/[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}/i`. Assert zero matches outside `content/faq.ts` and `content/speakers.ts` (organiser contact addresses, which are intentionally public). Assert the Sheet ID appears in no tracked file. |
| INV-4-T | 18+ only | Assert `PRAGMA table_info(registrations)` returns no column matching `/dob\|age\|birth\|guardian\|parent/`, except `age_confirmed`. Assert a payload without `ageConfirmed: true` returns `AGE_NOT_CONFIRMED` with HTTP 400. |
| INV-5-T | Zero third-party tracking | Grep the built `out/` directory for every entry in `BLOCKED_HOSTS`. Assert zero matches. Assert `public/fonts/` contains the woff2 files and that no `@font-face` `src` points off-origin. |
| INV-6-T | Zero recurring cost | Manual review at each milestone close. Every dependency checked against its free-tier terms; result recorded in §7. |
| INV-7-T | Permanent production URL | Assert `PROD_URL` contains neither `-git-` nor `localhost` nor `127.0.0.1`. Manual confirmation before any external submission. |
| INV-8-T | No claim without a number or source | Lint every module in `content/` against `BANNED_ADJECTIVES`. Assert zero matches. Assert every entry in `myths.ts` and `decade.ts` has a non-empty `source` or a numeric literal in its correction text. |
| INV-9-T | Brand marks unmodified | SHA-256 every file in `public/brand/` against the checksums recorded below. Any diff fails the build. |
| INV-10-T | Data expiry | Not automatable. A dated checklist item in `smoke.md` §7 and an `AGENT_LOG.md` entry on 2 January 2027. |

### Brand asset checksums (INV-9-T)

## 4. Negative tests

**More important than positive tests.** A form that accepts good input is easy; these catch the regressions that positive tests miss entirely.

| ID | Assertion |
|---|---|
| N-01 | Payload with `ageConfirmed: false` is **rejected** with `AGE_NOT_CONFIRMED`, HTTP 400, and no row is written |
| N-02 | Payload with a missing or invalid Turnstile token is **rejected** with `CHALLENGE_FAILED`, HTTP 403, and no row is written |
| N-03 | Payload with a malformed email (`"notanemail"`) is **rejected** with `INVALID_EMAIL`, HTTP 400 |
| N-04 | A response received with `type: "opaque"` is treated as **failure** by `lib/api.ts`, never as success. Guards against a `no-cors` regression |
| N-05 | A request from an origin not in the CORS allowlist is **rejected** at the preflight |
| N-06 | The sixth submission from one IP within an hour is **rejected** with `RATE_LIMITED`, HTTP 429 |
| N-07 | When the D1 write throws, the response is `STORE_UNAVAILABLE` HTTP 503, the fallback email fires, and **no success state renders** |
| N-08 | When the D1 write succeeds but the Sheets write throws, the response is still HTTP 200 success, the row exists with `mirrored_at IS NULL`, and the resync routine picks it up. A mirror failure must never fail a registration |
| N-09 | A payload containing an unexpected extra field (e.g. `dob`) is **rejected** or the field silently dropped — never written. Guards INV-4 against a client-side regression |
| N-10 | Content lint **fails** when a banned adjective is introduced into any `content/` module. Verify by deliberately adding one and confirming a non-zero exit |

N-10 is the one people skip. Run it once deliberately: a lint that has never failed has not been shown to work.

## 5. Telemetry

**None.** No analytics, no error reporting service, no session recording (INV-5).

What is recorded: Cloudflare Worker logs, retained by Cloudflare's default policy, containing `registrationId`, `code`, and request timing. No personal data (INV-3).

The consequence, stated honestly: you will not know how many people visited the site or where they dropped off. That is an accepted cost of INV-5, and `product.md` §6 chooses attendance over page views precisely because the vanity metric is unavailable anyway.

## 7. Recorded verdicts

Written **after** a milestone, not before. Criteria alone are aspiration; a verdict with evidence per line is what catches a milestone being 60% done and called finished.

**PASS only where a test or a recorded live result backs it.** Not inspection, not "it obviously works."

**Never round up a PARTIAL.** This is the strongest temptation in the system — one criterion short, everything else green, the milestone obviously basically done. Record the PARTIAL. On this project the most likely candidate is M1: the site will look finished while `myths.ts` and `decade.ts` are still thin, and those two are the entire differentiator.
